# ValueCell WEB 设计哲学与规范
### 如果乔布斯来做这个产品

> "设计不是外观和感觉。设计是它如何运作。" —— Steve Jobs

本文档不是一份"改版建议"，而是一份**设计宪法**。它规定了 ValueCell WEB 端从今往后应该如何被构想、被建造、被评判。任何一个新页面、新组件、新功能，如果说不出它符合本文档哪一条原则，就不应该被做出来。

## 第一部分：为什么要重来

打开今天的 ValueCell 首页，你会同时看到：三个市场指数卡片、一个新闻智能体的消息流、一个自选股列表、一个添加股票按钮、一个底部输入框、左侧一整列图标导航。**六个视觉焦点，同一时间争抢用户的注意力。**

这不是一个产品的问题，这是每一个由工程师主导、按"功能清单"堆砌出来的产品的通病：*我们做了这个功能，所以它必须被放在界面上*。

乔布斯从不这样想问题。他会走进会议室，看着这个画面，问一句话：

> "如果用户只能看一眼，我们希望她记住什么？"

现在的答案是：**什么都记不住，因为什么都在喊。**

我们看到的 ValueCell 本质上是一支由多个 AI 分析师组成的团队——研究员、交易员、新闻官、组合经理。这是一个了不起的想法。但今天的界面把这支"团队"呈现成了一堆仪表盘控件：sparkline、卡片网格、图标堆栈。**它看起来像 Bloomberg 终端的廉价复刻，而不是苹果会做的东西。**

Bloomberg 终端服务的是专业交易员，他们需要密度、需要一屏塞下 50 个数字。但 ValueCell 的目标用户，是希望有一个聪明朋友帮他打理投资的普通人。**密度是错误的度量衡。信任感才是。**

这就是我们重新设计的起点：**把 ValueCell 从"一个金融仪表盘"变成"一个你信任的人"。**

## 第二部分：一个句子说清楚这个产品

乔布斯设计 iPod 时的名言是："一千首歌，装进口袋。"不是"MP3播放器，24GB存储，支持多种编码格式"。

如果我们用同样的方式描述 ValueCell，它应该是：

> **"和一个从不睡觉、永远诚实的投资顾问对话。"**

不是"多智能体金融平台"。不是"AI驱动的量化交易与研究系统"。是**一段对话**。

这句话必须成为每一个设计决策的试金石。任何让"对话"这件事变得不是第一位的设计，都是错的。今天侧边栏里那一列智能体图标——研究员、交易员、新闻官——分别是不同的入口、不同的会话、不同的界面。这违背了"一个句子"。**用户不应该知道自己在和"哪个智能体"说话，她只应该觉得自己在和"ValueCell"这一个存在对话，而这个存在恰好懂研究、懂交易、懂新闻。**

这不是产品缩水，这是产品的诚实呈现。多智能体架构是我们的实现细节，不是用户需要理解的心智模型。**苹果从不让用户理解 A5 芯片的架构，他们只让用户感觉"更快了"。**

## 第三部分：设计哲学的七条戒律

### 戒律一：先说"不"

乔布斯：*"人们以为专注就是对该专注的事情说好。不是这样的，专注意味着对上百个其他好点子说不。"*

今天 ValueCell 首页上的每一个元素单独看都是"好点子"：市场指数很有用、自选股很有用、新闻推送很有用。但把它们全部塞进第一屏，就是对用户注意力的谋杀。

**我们的规则：新首页永远只有一个绝对主角——对话框。其余一切都是配角，且必须能被隐藏。**

### 戒律二：形式追随情感，而非追随功能

工业设计的老话是"形式追随功能"，但乔布斯的真正洞察更进一层：**形式追随情感**。用户打开炒股软件时的情绪状态是焦虑的——她担心自己的钱。一个像素级堆砌的仪表盘会放大这种焦虑（信息越多，越觉得自己漏掉了什么）。**一个安静、克制、像深呼吸一样的界面，才能配得上"帮用户做出理性决策"这个使命。**

这意味着：留白不是浪费空间，留白是在说"别慌，我们已经处理好了"。

### 戒律三：不惜代价追求单一性

现在系统里同时存在：Home 首页对话框、Agent Chat 独立会话页、Stock Detail 独立页、Agent Market 独立页、Settings 多个子页。**五套不同的界面语言，五套导航逻辑。**

苹果永远只有一个 Finder，一个 Mail，一个 Safari 的心智模型贯穿始终。我们必须把这些拆散的页面，收拢成**一个统一的对话式外壳（Shell）**，其他都是这个外壳里滑入滑出的"抽屉"，而不是各自为政的路由页面。

### 戒律四：看得见的诚实

金融产品最容易犯的错是"看起来很智能，实际上是黑箱"。用户问"特斯拉能不能买"，系统吐出一句"建议观望"——用户没有任何理由相信这句话。

乔布斯做产品从不掩饰复杂度，他只是把复杂度**编排**得很优雅（想想 Keynote 里过渡动画背后的复杂渲染管线）。同样，ValueCell 应该**展示 AI 的推理过程**——它读了哪份财报、算了哪个指标、参考了哪条新闻——但用一种优雅到不像"调试日志"的方式呈现。**透明不等于啰嗦，透明是一种设计出来的信任感。**

### 戒律五：颜色是意义，不是装饰

现有设计系统几乎是纯灰阶（`oklch` 中性色为主），只有涨跌数字用红绿。这个克制是对的方向，但还不够彻底——涨跌用的红绿和警告、危险的红绿在视觉上没有区分度，容易让用户把"跌了 2%"和"系统报错"混为一谈。

**新规则：色彩只用于三件事——① 资产涨跌（可配置红绿方向）② 系统的确定性反馈（成功/警告/风险）③ 唯一的品牌强调色，且只在最重要的行动点上出现一次。** 除此之外，界面必须是黑白灰。

### 戒律六：每一个像素都要能被解释

乔布斯会在苹果园区的会议室里，对着一个按钮的圆角问："为什么是这个数字？" 如果没人能回答，这个数字就是错的。

我们现有的设计系统里，圆角在 `8px / 10px / 12px / 16px` 之间随意切换，字号在 `14 / 16 / 18px` 之间没有统一逻辑。**新系统里，每一个数值都必须能追溯到一个数学关系（网格、比例），不允许"看着顺眼就用"。**

### 戒律七：产品的性格要统一

苹果的产品有性格：自信、克制、略带幽默但绝不轻浮。ValueCell 现在的文案是纯功能性的英文系统提示（"Type your message..."）。**它应该有性格：稳重、直接、像一个见多识广但从不炫耀的朋友。** 性格必须体现在每一句文案、每一个空状态、每一次报错里。

## 第四部分：砍掉的东西——比加什么更重要的是减什么

这是本文档最重要的一节。乔布斯式设计首先是一份"删除清单"。

| 现有元素 | 处置 | 理由 |
|---|---|---|
| 左侧竖排图标导航栏（固定 64px，承载 Home / Market / 各智能体 / Settings） | **删除，替换为可呼出的极简侧栏** | 永久占用 64px 宽度换来的是每天只用 2 次的导航。命令面板（⌘K）能做到同样的事，且默认不可见。 |
| 独立的 "Agent Market" 网格页 | **降级为对话中的一次自然推荐**，而非需要"逛"的页面 | 用户不会像逛应用商店一样逛智能体。她会说"帮我看看巴菲特会怎么想"，系统自然唤出该人格。逛页面这件事本身就是错的心智模型。 |
| 独立的 Agent Chat 路由页（`/agent/{name}`），每个智能体各有一套会话 | **合并为单一对话流**，智能体切换是对话内的"角色标签"而非页面跳转 | 用户的问题经常跨领域（"这只股票值得买吗，如果买，怎么设置自动交易"），被人为拆成多个页面是反人类的。 |
| 首页三个市场指数 sparkline 卡片，永久占据顶部 | **删除默认展示，改为按需召唤**（说"大盘怎么样"才出现，或在极简状态栏里以文字形式常驻） | 三个大盘指数对 80% 用户的日常决策没有直接帮助，却永久占用了黄金视觉区。 |
| "Add Stocks" 按钮 + 独立弹窗搜索 | **合并进统一输入框**：直接输入"关注 特斯拉"完成同样的事 | 减少一种独立的交互模式（模态框），让一切动作回归对话这一种范式。 |
| Settings 内的 "Stock Color Mode" 藏在二级菜单 | **保留功能，但改为对话中一次性引导设置**（"你更习惯涨红跌绿，还是涨绿跌红？"），此后常驻但不需要单独页面翻找 | 减少"设置迷宫"，把配置变成一次对话式的引导。 |
| 消息里穿插的原始技术术语（`component_type`、`tool_call` 等在部分渲染器里外露） | **彻底清除**，用户永远不该看到任何实现细节的痕迹 | 诚实展示"推理过程"≠暴露工程实现。见戒律四。 |
| 深色模式 CSS 变量已定义但未启用/未打磨 | **本阶段不做**，宁可没有，不要做一个"能用但难看"的暗色模式 | 半成品比没有更伤品牌。等做就做到跟亮色模式一样精致。 |

删除之后，WEB 端只剩下**一个主外壳**：一个近乎空白的画布，中间是对话，边缘按需浮现信息。这才是我们要造的东西。

## 第五部分：信息架构重构

### 5.1 旧架构（路由驱动）

```
/                      Home（大盘 + 任务卡 + 自选股 + 输入框）
/home/stock/:ticker    独立股票详情页
/agent/:name           独立智能体会话页
/market/agents         独立智能体市场页
/settings/general      独立设置页
/settings/memory       独立设置页
```

六个平行页面，用户靠左侧图标在它们之间"跳转"。**跳转本身就是一种打断。**

### 5.2 新架构（外壳驱动，Shell + Surface）

只有一个持久化的外壳（Shell），其余一切都是在外壳里浮现/退场的"表面"（Surface），永远不发生整页跳转、永远不丢失对话上下文。

```
Shell（永久存在，占满视口）
├── TopBar（40px，极简：品牌标记 · 会话标题 · 命令面板入口 · 头像）
├── ConversationCanvas（主画布，占据 100% 宽度，除非有 Surface 被召唤）
│     └── 消息流 + 底部悬浮输入条
└── Surface（按需从右侧滑入，宽度 0 → 420px，永不遮挡对话）
      ├── StockSurface     （问到具体标的时浮现）
      ├── PortfolioSurface （问到组合/持仓时浮现）
      ├── StrategySurface  （问到策略/自动交易时浮现）
      ├── ReportSurface    （深度报告的完整排版视图）
      └── CommandPalette   （⌘K 呼出，承担原侧边栏的全部导航职能）
```

**核心变化：从"多页面 + 固定侧栏"变成"单画布 + 情境化侧翼"。** 用户的心智负担从"我现在在哪个页面、怎么切换"降为零——她只需要说话。

### 5.3 顶层信息层级（这是本次重构唯一的"层级"）

```
Level 0  对话本身                 —— 永远存在，永远是主角
Level 1  与当前对话相关的情境信息   —— Surface，按需浮现，可一键收起
Level 2  全局但低频的操作           —— 命令面板 ⌘K，默认隐藏
Level 3  账户与系统设置             —— 命令面板的子集，绝不单列入口
```

没有 Level 4。如果一个功能重要到需要更深的层级，说明它应该被重新设计，而不是被藏得更深。

## 第六部分：视觉语言系统

现有系统已经用了 `oklch` 色彩空间和 Tailwind 4 + Radix，这是对的基础，我们不推倒重来，而是**做减法、立规矩、加灵魂**。

### 6.1 网格与间距——8pt 网格 + 一个例外

```
基准单位 = 4px
间距刻度：4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96 (px)
```

例外：对话消息的行内呼吸感使用 **1.5 倍行高**而非固定间距，因为阅读节奏应该由字体自己的度量决定，而不是被网格粗暴切割。

### 6.2 圆角——只留两个值

```css
--radius-control: 12px;   /* 按钮、输入框、chip、tag */
--radius-surface: 20px;   /* 卡片、浮层、Surface 面板 */
--radius-full:    9999px; /* 头像、圆形按钮 */
```

删除 8px / 10px / 16px 这些历史遗留值。**两个尺寸，讲得清楚为什么：控件用小圆角保持"可点击"的机械感，容器用大圆角传达"柔软、被信任"的容器感。**

### 6.3 色彩系统

保留现有 oklch 中性色阶作为骨架（它已经很克制），但重新定义语义角色，杜绝滥用：

```css
/* 中性骨架（沿用现有 oklch 灰阶，只做角色重命名，不改数值） */
--ink-100: oklch(0.145 0 0);   /* 主文字 */
--ink-60:  oklch(0.556 0 0);   /* 次要文字 */
--ink-20:  oklch(0.922 0 0);   /* 分割线 / 边框 */
--paper:   oklch(1     0 0);   /* 画布底色 */
--paper-soft: oklch(0.985 0 0); /* 极浅灰底，用于 Surface 背景，与画布做 1.5% 的亮度区分 */

/* 品牌强调色——唯一的彩色，克制使用 */
--brand: oklch(0.52 0.18 255);   /* 深邃蓝紫，只用于：主 CTA、AI 正在说话时的呼吸光、链接 */

/* 语义反馈色——与"涨跌色"完全隔离，避免混淆 */
--signal-success: oklch(0.6 0.14 155);
--signal-warning: oklch(0.75 0.15 80);
--signal-danger:  oklch(0.55 0.2  25);

/* 资产涨跌色——独立的语义域，用户可切换方向 */
--asset-up:   var(--user-preference);  /* 默认红或绿，遵循已实现的双模式设置 */
--asset-down: var(--user-preference);
```

**规则：一屏之内，彩色元素不得超过 3 处**（品牌色 CTA、一处涨跌数字、必要时一处反馈提示）。其余全部是黑白灰。这比现在的设计克制得多，也正因如此才显得每一处颜色都有分量。

### 6.4 字体排印——建立真正的比例关系

现有字号（14/16/18px）之间没有数学关系。新系统采用 **1.25 倍（大三度）比例**，从对话正文的 16px 基准向两端展开：

```
--text-caption:  12px   /* 时间戳、元信息 */    line-height 16px
--text-body:     16px   /* 对话正文，永远的基准 */ line-height 26px（1.625，专为长文阅读优化）
--text-emphasis: 20px   /* 卡片标题、强调数字 */  line-height 28px
--text-title:    25px   /* Surface 面板标题 */    line-height 32px
--text-display:  40px   /* 唯一的"大数字"场景：组合总值、股价 */ line-height 46px

字重只用两档：
--weight-regular: 430   /* 正文（可变字体的 430，比标准 400 略厚，屏幕阅读更舒适）*/
--weight-medium:  560   /* 强调：标题、数字、按钮文字 */
```

**杜绝使用 semibold(600)/bold(700) 之外的其他字重组合**——现有代码里 medium/semibold 混用没有统一逻辑，新规则是：**正文用 regular，任何需要"被看见"的文字用 medium，仅此而已**。

字体本身：系统字体栈保持不变（性能优先，这是对的），但为"大数字"场景（组合总值、股价）启用等宽数字特性（`font-variant-numeric: tabular-nums`），**这样数字跳动时不会引起布局抖动**——这是一个只有强迫症级别的团队才会在意的细节，也正是苹果会在意的细节。

### 6.5 阴影与层次——用光影讲物理关系，不是随便加阴影

```css
--elevation-0: none;                                          /* 画布本身 */
--elevation-1: 0 1px 2px rgba(17,17,17,0.04);                  /* 静止卡片，几乎不可见 */
--elevation-2: 0 8px 24px -4px rgba(17,17,17,0.08);            /* 悬浮态 / Surface 面板 */
--elevation-3: 0 24px 48px -12px rgba(17,17,17,0.18);          /* 命令面板 / 模态层 */
```

每一级阴影对应一个真实的"离画布距离"的物理隐喻：Surface 面板飘在对话之上，命令面板飘在最上层。**阴影不是装饰，是空间关系的诚实表达。**

### 6.6 图标——一套语言，不是两套

现有代码混用了自定义 SVG 图标集和 Lucide React。**新规则：全站图标只用一个来源（Lucide，线性、2px 描边、圆角端点），品牌相关的头像/Logo 除外。** 图标粗细必须与当前字重呼应——描边 1.5px 对应 regular 文字，2px 对应 medium 文字场景。

## 第七部分：逐页重新设计（WEB）

以下设计针对 **1440×900 及以上的桌面浏览器视口**，这是 ValueCell WEB 端的主战场。

### 7.1 主外壳（The Shell）—— 一切的起点

```
┌──────────────────────────────────────────────────────────────────┐
│  ○ ValueCell                              与你的 AI 顾问对话中  ⌘K  ⚙ │ ← 40px TopBar，
├──────────────────────────────────────────────────────────────────┤    近乎透明，滚动时才显影
│                                                                    │
│                                                                    │
│                     （空状态：见 7.2）                              │
│                     或                                             │
│                     （消息流：见 7.3）                              │
│                                                                    │
│                                                                    │
│                                                                    │
│  ┌──────────────────────────────────────────────────────────┐    │
│  │  问我任何关于投资的问题...                            ↑    │    │ ← 悬浮输入条，
│  └──────────────────────────────────────────────────────────┘    │   永远贴底，
│                                                                    │   宽度随视口居中收窄
└──────────────────────────────────────────────────────────────────┘
```

关键决策：

- **TopBar 高度 40px，背景透明，仅在向下滚动消息流时才出现 1px 底部分割线与轻微毛玻璃**——它应该感觉"几乎不存在"，直到你需要它。
- **没有左侧导航栏。** 一切导航通过 `⌘K` 命令面板完成（见 7.6）。这个决定看起来激进，但这正是"先说不"的具体实践：导航栏是给不知道自己要做什么的用户看的地图，而 ValueCell 的用户永远知道自己要做什么——"我想问点什么"。
- **输入条永远存在，永远居中，永远是视觉重心。** 未聚焦时宽度 680px；聚焦时舒展到 760px 并轻微上浮 4px，配合阴影从 `elevation-1` 过渡到 `elevation-2`——这个 200ms 的呼吸感，是用户和产品的第一次"握手"。

### 7.2 空状态——第一印象决定一切

乔布斯对首次开箱体验的偏执众所周知（iPhone 包装盒的开盖阻尼都是设计过的）。ValueCell 的"空状态"就是我们的开箱体验，每一次会话重新开始都会看到它，**它必须配得上被反复看到**。

```
                          ◇
                    （品牌标记，
                  呼吸般的微光动画，
                   周期 3s，透明度 
                    0.7 → 1 → 0.7）

                 你好，我是 ValueCell

           说点什么，我们从这里开始。

     ┌───────────────┐ ┌───────────────┐ ┌───────────────┐
     │ 看看我的组合    │ │ 研究一家公司    │ │ 设置自动交易    │
     │ 表现如何       │ │              │ │              │
     └───────────────┘ └───────────────┘ └───────────────┘
```

细节规范：

- 品牌标记不是静态 Logo，是一个**极慢速的呼吸动画**——暗示"它一直醒着，一直在思考"。这比任何文案都更能传达"7×24 小时为你工作"的产品承诺。
- 三张建议卡片**永远根据用户历史动态生成**，不是写死的三句话。一个从没用过组合功能的新用户，和一个天天看盘的老用户，看到的建议应该完全不同。**这是"千人千面"第一次真正体现产品智能，而不是靠一句"AI 驱动"的文案自吹自擂。**
- 卡片本身：`elevation-1`，hover 时上浮 2px 加 `elevation-2`，过渡 150ms `ease-out`。**不允许有任何"跳动"感的动画，一切位移必须在 4px 以内**——这是克制感的具体数字化标准。

### 7.3 对话消息流——AI 的"看得见的思考"

这是整个重设计里最重要的组件，因为它每天被看几十次。

```
┌────────────────────────────────────────────────────────┐
│  你                                                       │
│  特斯拉现在能买吗？                                          │
└────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────┐
│ ◇  正在为你研究                                            │
│                                                          │
│    ✓ 已读取 2025 Q3 财报            0.6s                  │
│    ✓ 已核对近 7 日新闻情绪            0.9s                  │
│    ● 正在评估估值水平...                                    │
│                                                          │
└────────────────────────────────────────────────────────┘

      ↓ 完成后，思考过程收起为一行可展开的元信息，结果主体浮现 ↓

┌────────────────────────────────────────────────────────┐
│ ◇  特斯拉（TSLA）· 现价 $440.07  ▼4.63%                    │
│                                                          │
│  基本面稳健，但当前估值已price-in了明年的增长预期。          │
│  短期波动风险偏高，建议观望或小仓位试探。                    │
│                                                          │
│  · 现金流：健康，自由现金流同比+18%                          │
│  · 估值：动态市盈率处于三年区间的78分位，偏高                 │
│  · 情绪：近7日新闻情绪中性偏正面                             │
│                                                          │
│  基于 3 处数据来源 · 用时 4.2s                              │
│                                                          │
│  [ 深入研究 ]  [ 加入自选 ]  [ 设置价格提醒 ]                │
└────────────────────────────────────────────────────────┘
```

设计规则：

1. **用户消息永远右对齐、无头像、浅灰底色（`--paper-soft`）**——安静，不抢戏。
2. **AI 消息永远左对齐，无气泡边框，仅用一个 4px 圆点标记（呼吸动画中）作为"正在说话"的身份标识**，不使用夸张的卡通头像。这传达"这是一个统一的智慧体，而不是某个具体的卡通形象在讲话"——呼应第二部分"一个句子"的原则。
3. **推理过程用清单形式逐条完成打勾**，每条右侧标注真实耗时（哪怕只有 0.6 秒也要标出来）——这是"戒律四：看得见的诚实"的具体实现。用户会下意识地把"每一步都写清楚时间"的界面，和"靠谱"划等号。
4. **推理过程在完成后自动折叠为一行**（"基于 3 处数据来源 · 用时 4.2s"，可点击展开还原完整清单）——保留可追溯性，但不让历史消息里堆满已经完成的过程日志。
5. **结论永远是第一句话，且用陈述句而非模棱两可的免责辞令。** "短期波动风险偏高，建议观望"比"综合来看可能需要谨慎评估市场因素"要诚实一百倍。这不是给用户下命令，是尊重用户的时间。
6. **行动按钮永远是次要样式（ghost/outline），永远在消息最后一行，永远不超过 3 个。** 它们不该抢过内容本身的风头。
7. **数字必须用 `tabular-nums` 等宽数字**，涨跌箭头颜色遵循用户在初次引导中设置的偏好。

### 7.4 情境侧翼（Surface）—— 按需浮现，绝不常驻

当对话涉及具体股票、组合或策略时，右侧以 **320ms `cubic-bezier(0.22, 1, 0.36, 1)`**（先快后缓的"过冲回弹"曲线，非线性缓动）从 0 宽度滑出到 420px：

```
┌──────────────────────────────────┐
│  TSLA                          ⨯ │ ← 可随时一键收起，
│  Tesla, Inc.                     │   不影响左侧对话继续
│                                   │
│  $440.07                         │
│  ▼ -$21.40 (-4.63%)  今日          │
│                                   │
│  ┌─────────────────────────────┐ │
│  │       （60日走势图，          │ │
│  │        无网格线，              │ │
│  │        仅在hover时显示数值）    │ │
│  └─────────────────────────────┘ │
│                                   │
│  行业        非必需消费品·汽车      │
│  市值        $1.41T               │
│  市盈率(TTM)  118.4                │
│                                   │
│  ──────────────────────────────  │
│  ⌘ 继续问关于 TSLA 的问题           │
└──────────────────────────────────┘
```

规则：

- **图表本身移除所有网格线、坐标轴刻度**，只留一条走势曲线和一个可交互的 hover 提示——这是"戒律六"在数据可视化上的具体应用：如果一根网格线不能被解释为"用户此刻需要它"，就删掉它。
- **面板永远可以被"问下去"**——面板底部有一条极简的引导（"继续问关于 TSLA 的问题"），点击即聚焦回主输入框并预填上下文。**Surface 不是一个信息孤岛，它是对话的延伸，绝不能让用户觉得自己"跳出"了对话。**
- 面板的存在与否，**永远由对话内容决定，用户不能手动"打开股票面板"**——因为一旦允许手动打开，它就会变成又一个需要维护心智模型的独立界面，违反戒律三。

## 第八部分：动效哲学

乔布斯对动效的态度不是"炫技"，而是**"每一个动画都必须回答一个物理问题：这个东西从哪里来，要到哪里去。"**

### 8.1 唯一合法的缓动函数家族

```css
--ease-standard: cubic-bezier(0.4, 0, 0.2, 1);   /* 状态变化：淡入淡出、颜色过渡 */
--ease-enter:    cubic-bezier(0.22, 1, 0.36, 1);  /* 元素进入：面板滑入、卡片浮现，
                                                       带轻微过冲，像被稳稳接住 */
--ease-exit:     cubic-bezier(0.4, 0, 1, 1);      /* 元素离开：干脆利落，不拖泥带水 */
```

**全站禁止使用默认的 `ease` 或 `linear`。** 线性动画是没有生命的东西移动的方式，物理世界里没有匀速。

### 8.2 时长规则——按"距离"分级，不是拍脑袋

```
微反馈（按钮按下、勾选）        100–120ms
局部状态变化（hover、聚焦）     150–200ms
组件进入/离开（Surface、卡片）  250–320ms
场景级转场（命令面板、报告视图） 350–400ms
```

**规则：时长必须与被移动元素的"视觉距离"成正比。** 一个按钮的按下反馈用 400ms 会显得迟钝笨重；一个 420px 宽的面板用 100ms 滑入会显得突兀粗暴。这不是审美偏好，是基本的物理直觉。

### 8.3 AI"正在思考"的呼吸感——产品的心跳

前文多次提到的"呼吸动画"（品牌标记、AI 消息标识的微光脉动）需要统一参数，因为它会成为整个产品最高频出现的动效，某种意义上它就是 ValueCell 的心跳：

```css
@keyframes breathe {
  0%, 100% { opacity: 0.55; transform: scale(0.97); }
  50%      { opacity: 1;    transform: scale(1);    }
}
/* 周期 2.4s，ease-in-out，无限循环，永远不能有"卡顿感"——
   这个动画一旦掉帧，用户会下意识觉得"系统卡住了"，
   所以必须用 transform + opacity（GPU 加速属性），
   绝不允许用会触发重排的属性（width/height/margin）实现。 */
```

### 8.4 文字的出现方式——打字机，但要克制

流式响应不是简单地逐字符 append，而是**逐词淡入 + 4px 上移**（不是逐字符，逐字符的"电报感"廉价且降低阅读速度）。数字（价格、百分比）例外：数字必须整体一次性出现并伴随一次轻微的颜色闪烁标记"这是新数据"，因为**逐字动画会让人在数字上产生误读的瞬间焦虑**（金融数字上，0.1 秒的误读都是不可接受的）。

## 第九部分：文案的声音

乔布斯对文案的偏执不亚于对像素的偏执（想想"1000 songs in your pocket"）。ValueCell 的声音应该是：

**稳重、直接、留白，绝不居高临下，绝不假装万能。**

| 场景 | 错误示范（现状/常见AI产品腔调） | ValueCell 的声音 |
|---|---|---|
| 空状态引导 | "欢迎使用 ValueCell！开始探索强大的 AI 投研功能吧！" | "你好，我是 ValueCell。说点什么，我们从这里开始。" |
| 加载中 | "AI 正在处理中，请稍候..." | "正在为你研究" + 具体在做什么的清单 |
| 无法回答 | "抱歉，我无法理解您的请求，请重新描述。" | "这个我还不确定。要不你换个说法，或者告诉我更多细节？" |
| 风险提示 | "投资有风险，入市需谨慎。" （生硬的法律免责） | 融入结论本身："短期波动风险偏高，建议观望"——风险提示就是分析的一部分，而不是脱离内容的一句法律贴纸 |
| 错误状态 | "Error: Connection timeout (Code 504)" | "网络好像开小差了，我再试一次" + 自动重试，不需要用户点按钮 |
| 交易确认 | "订单已提交，订单号：#TX20250131001" | "已经帮你买入 0.1 个比特币，现在仓位占组合的 12%。" —— 说人话，说清楚这笔操作在大局中的意义 |

**规则总结：**
1. 永远用第一人称"我"而非"系统""AI 助手"——它是一个存在，不是一个工具。
2. 永远解释"这对你意味着什么"，而非单纯陈述发生了什么。
3. 永远不用感叹号堆砌热情（"太棒了！"），克制本身就是自信的体现。
4. 中文语境下杜绝生硬直译腔（"抱歉给您带来不便"），说人话。

## 第十部分：签名时刻——那些让人记住的细节

每一个伟大的苹果产品都有几个"意料之外"的细节，用户说不清楚为什么喜欢，但就是记住了（iPhone 的橡皮筋回弹滚动、macOS 的窗口关闭"缩进 Dock"动画）。ValueCell WEB 端应该埋下这些细节：

### 10.1 输入框的"倾听感"

当用户开始打字，输入框边框不是生硬地变色，而是**从中心向两端浮现一圈极细的品牌色光晕**（类似 macOS Siri 的听筒动画，但更克制、只有 1px 宽度），暗示"它在认真听你说话"。松开焦点后光晕在 300ms 内散去。

### 10.2 数字翻牌效果

组合总值、股价这类"大数字"更新时，不是瞬间跳变，而是**用类似老式翻页时钟的数位滚动动画**（每一位数字独立滚动到新值，200ms，`ease-standard`）。这个细节的价值在于：**用户能"感觉到"钱在变化，而不是突然看到一个陌生数字**，这对缓解金融焦虑有真实的心理学作用。

### 10.3 深夜模式的自动问候

TopBar 的问候语（"你好，我是 ValueCell"）会根据本地时间微调——凌晨时段（0:00–5:00）显示"这么晚还在看盘？我陪你。" 这不是噱头，这是**让用户觉得产品真的懂她的生活节奏**，是从功能思维到情感思维的分水岭。

### 10.4 首次盈利的庆祝

当用户第一笔纸上交易/实盘交易首次转为正收益，Surface 面板会有一次**极其克制的一次性彩带动画**（不超过 800ms，不影响任何操作，只出现一次，之后永不重复）。乔布斯从不滥用惊喜，但会在关键的情感节点上给一次——这是**尊重用户情绪价值的仪式感**，而不是游戏化的廉价勋章系统。

### 10.5 离开时的告别

关闭标签页或长时间无操作后返回时，输入框的 placeholder 会短暂显示"欢迎回来"，随后 2 秒淡回默认的"问我任何关于投资的问题..."。**连接感是靠这些几乎不会被人有意识注意到的瞬间堆积出来的。**

## 第十一部分：设计评审清单

任何新设计提案，在被批准前，必须能对以下问题逐条给出诚实回答（这不是走过场，任何一条答不上来就打回）：

1. **这个功能是否让"对话"这件事变得不再是第一位？** 如果是，重做。
2. **能否找到已经存在的元素来复用这个能力，而不是新增一个视觉焦点？**
3. **它是否引入了新的颜色？如果是，它属于"品牌色 / 语义反馈色 / 涨跌色"中的哪一种？如果都不是，删除。**
4. **它的圆角、间距、字号是否能在第六部分的系统里找到对应值？如果需要一个新数值，为什么现有系统不够用？**
5. **它的动效时长是否符合"距离决定时长"的规则？**
6. **移除这个功能后，产品是否变差了，还是仅仅变得"不一样"？** 只有前者才值得保留。
7. **这段文案，读起来像一个人在说话，还是像一份系统日志？**
8. **一个从未用过 ValueCell 的人，看到这个界面 3 秒内，知道下一步该做什么吗？**
9. **这是我们必须做的，还是仅仅因为"竞品有"？** 竞品有不是理由。
10. **如果乔布斯现在站在你身后看这个原型，他会问的第一个问题是什么？你能回答吗？**

## 第十二部分：落地路线图

不追求一次性推翻重来（那是不负责任的工程决策），而是按"用户能立刻感知到差异"的顺序推进：

### 阶段一：地基（视觉系统 + 外壳）
- 落地第六部分的色彩 / 字号 / 圆角 / 阴影 token，替换现有零散数值
- 搭建新的 Shell 布局（TopBar + 单一 ConversationCanvas），**先与现有路由页面共存，不删旧页面**
- 命令面板 ⌘K 原型（先只做"搜索历史对话"一个功能）

### 阶段二：对话核心体验
- 重做消息气泡组件：思考清单、折叠态、行动按钮规范
- 悬浮输入条的呼吸/倾听动效
- 流式响应的逐词淡入 + 数字翻牌动效

### 阶段三：情境侧翼替代旧路由页
- Surface 面板承接原 Stock Detail / Portfolio 的信息，**验证无损后再下线旧独立页面**
- ReportSurface 承接财报/回测长内容展示

### 阶段四：删除与收尾
- 正式下线左侧导航栏、Agent Market 独立页、旧 Settings 多级页面
- 全站文案按第九部分重写
- 埋入第十部分的签名细节，逐一验收动效手感

### 阶段五：极致打磨
- 逐屏走查评审清单（第十一部分），任何一条不达标退回重做
- 性能验收：所有动效必须在中低端笔记本上保持 60fps，任何掉帧的动效直接砍掉而不是"优化着用"

**原则：宁可晚发布，不可发布一个"差不多"的细节。** 乔布斯曾经因为一个图标的圆角问题让团队推迟发布——这不是传说里的偏执，这是对用户的尊重被具象化的样子。

## 尾声

这份文档描述的不是一次"UI 改版"，而是一次**产品心智模型的手术**：把 ValueCell 从"一个功能齐全的金融工具"，变成"一个你愿意每天开口说话的存在"。

工具是用来使用的。伙伴，是用来信任的。

如果这次重构做对了，用户不会说"这个界面真好看"。他们会说的是：

> **"我打开电脑的第一件事，就是问问它今天该怎么办。"**

这才是设计真正的胜利——**当设计本身消失，只剩下信任。**
